# muis

یک پخش‌کننده‌ی موسیقی فارسی. جستجو، پخش، متن ترانه، و اشتراک‌گذاری پلی‌لیست بین دستگاه‌ها.

## راه‌اندازی

```bash
bun install
bun run dev
```

همین. **هیچ تنظیمی لازم نیست** — نه کلید API، نه حسابی در سرویس دیگر، نه نصب پایگاه‌داده. یک
کلون تازه از این مخزن بالا می‌آید و کار می‌کند.

پیش‌نیاز: [Bun](https://bun.sh) ۱.۴ یا بالاتر (یا Node ۲۲.۵ به بالا).

## داده کجاست

حساب‌ها و پلی‌لیست‌های اشتراکی یک سند JSON هستند — یک شیء با سه نگاشت. این سند بسته به
جایی که برنامه اجرا می‌شود جایی نگه داشته می‌شود:

| کجا اجرا می‌شود | کجاست | چطور |
| --- | --- | --- |
| دسکتاپ و پریویو | `.data/muis.json` | خودکار در نخستین درخواست ساخته می‌شود |
| ورکر منتشرشده‌ی Cloudflare | پایگاه‌داده‌ی D1 | با `d1_databases` در `wrangler.jsonc` |

روی ورکر Cloudflare دیسک ماندگاری وجود ندارد، پس فایل بعد از هر راه‌اندازی دوباره پاک
می‌شود. اگر `d1_databases` در `wrangler.jsonc` فعال باشد، برنامه همان سند را در **یک ردیف**
از D1 می‌خواند و می‌نویسد، پس حساب‌ها از هر ری‌استارتی جان سالم به در می‌برند. تا وقتی آن
binding نباشد، برنامه حساب‌ها را در حافظه نگه می‌دارد: ثبت‌نام و اشتراک‌گذاری کار می‌کند،
فقط با ری‌استارت پاک می‌شود. `GET /api/auth?action=mode` می‌گوید کدام‌یک فعال است.

جدول `muis_document` را خود برنامه در نخستین استفاده می‌سازد؛ اگر ترجیح می‌دهی از قبل آماده
باشد، `migrations/0001_document.sql` را روی دیتابیس اجرا کن. اگر D1 در دسترس نباشد — جدول
ساخته نشده باشد، یا حساب دسترسی نداشته باشد — برنامه ثبت‌نام را متوقف نمی‌کند: حساب‌ها در
حافظه می‌مانند، `mode` صادقانه `memory` را برمی‌گرداند، و دلیل خطا در لاگ ورکر نوشته می‌شود.

## کتابخانه و حساب

پلی‌لیست‌ها، علاقه‌مندی‌ها، سابقه‌ی پخش و تاریخچه‌ی جستجو به **اکانت** می‌چسبند، نه به دستگاه.
پس با ورود به حساب، همه‌چیز روی هر دستگاهی برمی‌گردد.

- ورود به حساب: سندِ حساب خوانده می‌شود و جایگزین نسخه‌ی دستگاه می‌شود.
- اگر حساب هنوز کتابخانه‌ای نداشته باشد ولی دستگاه دارد، همان دستگاه بالا فرستاده می‌شود —
  کسی که قبل از ساختن حساب پلی‌لیست ساخته، چیزی از دست نمی‌دهد.
- هر تغییر، با کمی تأخیر (۰٫۸ ثانیه) روی حساب نوشته می‌شود.
- قاعده‌ی هم‌زمانی: **حساب برنده است.** سند جایگزین می‌شود، نه ادغام — پس پلی‌لیستی که روی یک
  دستگاه پاک شد، روی دستگاه بعدی هم پاک می‌ماند.

آنچه **همگام نمی‌شود** و عمداً می‌ماند: فایل‌های دانلودشده (بایت‌های صوتی در IndexedDB هر
دستگاه‌اند) و تنظیمات.

## بکاپ

```bash
bun run backup                              # می‌سازد
bun run restore .data/backups/muis-....json
```

بکاپ‌ها در `.data/backups/` می‌نشینند. بازگردانی، نسخه‌ی فعلی را کنار می‌گذارد و پس از آن باید
سرور را دوباره راه‌اندازی کنی.

## آرشیو متنی

```bash
bun run export
```

می‌نویسد در `data/muis-data.json` — یک فایل متنی که **در گیت می‌ماند**: نام کاربری‌ها، و هر
پلی‌لیست اشتراکی با فهرست کامل آهنگ‌هایش.

سه چیز عمداً در آن نیست، و هر سه اسرارند نه داده:

- **هش رمز و نمک** — هدف حدس آفلاین. تاریخچه‌ی گیت برای همیشه می‌ماند؛ حذف فایل بعداً آن‌ها را
  از کلون‌های قبلی پاک نمی‌کند.
- **کدهای بازیابی** — هر کد یعنی تعیین رمز جدید، بدون داشتن رمز قبلی.
- **نشست‌ها** — شناسه‌ی نشست مستقیماً توکن ورود است. از هش هم بدتر، چون هیچ کاری لازم ندارد.

پس این فایل **آرشیو است، نه راه بازگرداندن ورود**. حسابی که از روی این فایل ساخته شود رمزی
برای راستی‌آزمایی ندارد و کسی نمی‌تواند واردش شود. برای جابه‌جا کردن یک پایگاه‌داده‌ی سالم،
همان `bun run backup` است.

خروجی مرتب و بدون زمان است، پس هر بار که داده‌ای عوض نشده باشد فایل هم عوض نمی‌شود و
`git diff` فقط تغییرات واقعی را نشان می‌دهد.

## طراحی

رابط کاربری بر پایه‌ی راهنمای iOS ساخته شده و از یک سیستم طراحی مشترک می‌خواند، نه از سلیقه‌ی
هر صفحه. دو تکه دارد و هر دو باید با هم عوض شوند:

**۱. متغیرهای CSS** — `src/styles.css`. رنگ‌ها با نام‌های اپل (`--ios-tint`, `--ios-separator`,
`--ios-surface`, …)، مقیاس تایپوگرافی (`type-large-title` تا `type-caption`)، شعاع‌ها
(`rounded-tile/card/sheet`)، متریال (`material`) و کلاس‌های تعاملی (`press`, `btn`,
`btn-filled/tinted/gray`).

**۲. ثابت‌های جاوااسکریپت** — `src/lib/design/`. `motion.ts` اسپرینگ‌ها و زمان‌بندی‌ها،
`tabs.ts` پنج تب اصلی به‌صورت یک enum و نگاشت مسیرها به تب‌ها.

### واژگان طراحی

هشت مفهوم، هشت تا کلاس و کامپوننت مشخص. هر کدام یک جا در کد دارند و همه‌جا با همین
نام‌ها صدا زده می‌شوند، تا یک صفحه‌ی تازه از صفر شروع نکند:

| مفهوم | کجا در کد |
| --- | --- |
| **Floating Glass Navigation** — ناوبری شناور | `TabBar` و `MiniPlayer`: `material` روی یک نوار `fixed` با فاصله از پایین صفحه |
| **Detached UI Elements** — المان‌های مستقل | `panel` و `card` در `styles.css`: هر المان یک پنل گرد با فاصله‌ی مشخص از همسایه |
| **Specular Highlights** — بازتاب لبه | کلاس `specular`: تیغه‌ی نورِ لبه‌ی شیشه، که بدون آن سطح فقط یک مستطیلِ مات است |
| **Cursor Reactive Spotlight** — نور موضعی | کلاس `spotlight` به‌همراه `usePointerLight` (`--mx`/`--my`): همان نور که با نشانگر می‌لغزد |
| **Magnification Dock** — بزرگ‌نمایی داک | اسپرینگ‌های `scale`/`y` در `DockItem` روی motion value، بدون re-render |
| **Ambient Mesh Gradient** — پس‌زمینه‌ی زنده | `mesh`، `mesh-accent` و `mesh-drift` در `styles.css` |
| **Staggered Scroll Reveal** — ورود مرحله‌ای | `Reveal`: هر المان یک ضرب بعد از قبلی، فقط یک بار |
| **Spring & Morphing Motion** — فنر و تغییر شکل | `snappy`/`standard` در `src/lib/design/motion.ts`، به‌علاوه‌ی `press` |

کامپوننت‌های پایه در `src/components/ios/` هستند و همه‌ی صفحه‌ها از آن‌ها ساخته می‌شوند:

| کامپوننت | نقش |
| --- | --- |
| `Screen` | عنوان بزرگ صفحه روی خودِ پس‌زمینه، بدون نوار ناوبری |
| `Section` / `Row` | فهرست گروهی: سربرگ، کارت، جداکننده، مقدار انتهای ردیف؛ `Row` با `plain` داخل یک `card` می‌نشیند |
| `Segmented` | کنترل بخش‌ها (آهنگ‌ها / پلی‌لیست‌ها / تاریخچه) |
| `SearchField` | میدان جستجوی iOS |
| `EmptyState` | تنها حالت «خالی» برنامه |
| `TabBar` / `MiniPlayer` | نوار تب و پخش‌کننده‌ی کوچک |

چند قاعده که همه‌جا رعایت می‌شود:

- **المان‌ها جدا از هم.** هر بخش، هر ردیف و هر دکمه یک پنل گرد با فاصله‌ی جداگانه است تا روی
  شیشه بنشیند و خودش یک شیء باشد؛ این کلاس `panel` است. تنها جایی که چند کنترل در یک شیء جمع
  می‌شوند، وقتی‌اند که خودشان یک فهرست‌اند — همان شکل تنظیمات iOS: یک `card` با خط‌های نازک
  بین گروه‌ها، و `Row` با `plain` تا پنل دوم نسازد.
- **روشن، پیش‌فرض.** پالت روشن در `:root` است و تاریک فقط یک بلوک `.dark` روی همان توکن‌هاست،
  پس هیچ کامپوننتی نمی‌پرسد در کدام حالتیم. سوییچ «حالت تاریک» در تنظیمات، و همان اسکریپت
  کوچک در `head` که حالت شیشه‌ای را می‌گذارد، اینجا را هم پیش از اولین رنگ‌آمیزی اعمال می‌کند —
  وگرنه هر بار که برنامه باز شود یک لحظه‌ی رنگ اشتباه دیده می‌شد.
- **حالت شیشه‌ای.** پنل‌ها روی کاور محو‌شده‌ی آهنگ شناورند و از آن نور عبور می‌دهند. کل
  افکت با `--surface-alpha`، `--panel-blur` و `--material-blur` در `styles.css` کنترل می‌شود؛
  سوییچ «حالت شیشه‌ای» در تنظیمات آن‌ها را صفر می‌کند و سطح‌ها را مات می‌کند، بدون آنکه
  چیدمان یا کنتراست تغییر کند. انتخاب در `localStorage` می‌ماند و پیش از اولین رنگ‌آمیزی
  توسط یک اسکریپت کوچک در `head` اعمال می‌شود.
- **عدسی، نه فقط مه.** روی داک و مینی‌پلیر یک لایه‌ی خالی به نام `lens-bend`
  می‌نشیند که فیلتر جابه‌جایی SVG (`muis-lens` در `GlassDefs`) را روی **پس‌زمینه** اعمال
  می‌کند؛ یعنی متن و المانی که از زیرشان رد می‌شود واقعا خم می‌شود، نه اینکه فقط مات شود.
  فیلتر دو مرحله دارد: یک کششِ کم‌بسامد و پرقدرت (ضخامت شیشه) و یک شکستِ ریزتر و ملایم‌تر
  (خودِ شکستِ نور). مهِ `lens` جدا و همیشه معتبر است و روی آن می‌آید، پس موتوری که `url()`
  را نپردازد شیشه‌ی ساده نشان می‌دهد، نه شیشه‌ی بی‌مه. این مقدار عمدا فقط با خاصیت
  استاندارد نوشته می‌شود: کرومیوم `url()` را از راه `-webkit-backdrop-filter` قبول می‌کند ولی
  چیزی رسم نمی‌کند، و نوشتن هر دو با هم باعث می‌شود بیلد فقط نسخه‌ی پیشوندی را نگه دارد.

- **هدف لمسی ۴۴ پیکسل.** هر چیزی که لمس می‌شود — از دکمه‌ی آیکونی تا ردیف فهرست — دست‌کم
  ۴۴pt بلند است.
- **بدون فاصله‌گذاری حروف.** وزیرمتن خطی پیوسته است؛ `tracking` اتصال حروف را می‌شکند.
- **اندازه‌ی قلم ثابت نیست.** مقیاس تایپوگرافی با `rem` نوشته شده تا بزرگ‌نمایی متن مرورگر
  آن را هم بزرگ کند — نزدیک‌ترین چیز به Dynamic Type در وب.
- **کاهش حرکت.** `prefers-reduced-motion` هم CSS و هم انیمیشن‌های JS را خاموش می‌کند.
- **یک دکمه، یک کار.** ردیف فهرست یک دکمه است و منوی بیشتر کنارش، نه درونش.

صفحه‌ی `/studio` یک نمونه‌کار جداگانه است: عمداً بیرون از `AppShell` و با متغیرهای خودش،
تا هیچ‌کدام از این‌ها را لمس نکند.

## چه چیزی در گیت هست و چه چیزی نیست

**هست:** کل کد، `bun.lock`، اسکیمای D1 در `migrations/`، آرشیو `data/muis-data.json`، و همین
راهنما. از روی همین مخزن، هر پایگاه‌داده‌ای از نو ساخته می‌شود.

**نیست:** خودِ فایل `.data/muis.json`. داخلش هش رمزها، کدهای بازیابی و نشست‌هاست، و
commit کردنش یعنی دادن یک ورودی آفلاینِ رایگان برای حدس‌زدن رمزها به هرکس که مخزن را ببیند —
و تاریخچه‌ی گیت آن را پس نمی‌گیرد. به‌جایش از `bun run backup` استفاده کن و آن فایل را جایی
امن نگه دار.

## استقرار

بیلد، خروجی ورکر Cloudflare می‌سازد:

```bash
bun run build
npx nitro deploy --prebuilt
```

پیش از این، `d1_databases` را در `wrangler.jsonc` پر کن. یک‌بار برای همیشه:

```bash
npx wrangler d1 create muis            # شناسه را می‌دهد
npx wrangler d1 execute muis --remote --file=migrations/0001_document.sql
```

شناسه را در `wrangler.jsonc` بگذار تا حساب‌ها روی سرور هم بمانند. اگر نام دیتابیس غیر از
`muis` است، همان را در `database_name` بنویس.
