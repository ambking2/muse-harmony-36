# muis

یک پخش‌کننده‌ی موسیقی فارسی. جستجو، پخش، متن ترانه، و اشتراک‌گذاری پلی‌لیست بین دستگاه‌ها.

## راه‌اندازی

```bash
bun install
bun run dev
```

همین. **هیچ تنظیمی لازم نیست** — نه کلید API، نه حسابی در سرویس دیگر، نه نصب پایگاه‌داده. یک
کلون تازه از این مخزن بالا می‌آید و کار می‌کند.

پیش‌نیاز: [Bun](https://bun.sh) ۱.۴ یا بالاتر (یا Node ۲۲.۵ به بالا).

## داده کجاست

حساب‌ها و پلی‌لیست‌های اشتراکی یک سند JSON هستند — یک شیء با سه نگاشت. این سند بسته به
جایی که برنامه اجرا می‌شود جایی نگه داشته می‌شود:

| کجا اجرا می‌شود | کجاست | چطور |
| --- | --- | --- |
| دسکتاپ و پریویو | `.data/muis.json` | خودکار در نخستین درخواست ساخته می‌شود |
| ورکر منتشرشده‌ی Cloudflare | پایگاه‌داده‌ی D1 | با `d1_databases` در `wrangler.jsonc` |

روی ورکر Cloudflare دیسک ماندگاری وجود ندارد، پس فایل بعد از هر راه‌اندازی دوباره پاک
می‌شود. اگر `d1_databases` در `wrangler.jsonc` فعال باشد، برنامه همان سند را در **یک ردیف**
از D1 می‌خواند و می‌نویسد، پس حساب‌ها از هر ری‌استارتی جان سالم به در می‌برند. تا وقتی آن
binding نباشد، برنامه حساب‌ها را در حافظه نگه می‌دارد: ثبت‌نام و اشتراک‌گذاری کار می‌کند،
فقط با ری‌استارت پاک می‌شود. `GET /api/auth?action=mode` می‌گوید کدام‌یک فعال است.

جدول `muis_document` را خود برنامه در نخستین استفاده می‌سازد؛ اگر ترجیح می‌دهی از قبل آماده
باشد، `migrations/0001_document.sql` را روی دیتابیس اجرا کن. اگر D1 در دسترس نباشد — جدول
ساخته نشده باشد، یا حساب دسترسی نداشته باشد — برنامه ثبت‌نام را متوقف نمی‌کند: حساب‌ها در
حافظه می‌مانند، `mode` صادقانه `memory` را برمی‌گرداند، و دلیل خطا در لاگ ورکر نوشته می‌شود.

## کتابخانه و حساب

پلی‌لیست‌ها، علاقه‌مندی‌ها، سابقه‌ی پخش و تاریخچه‌ی جستجو به **اکانت** می‌چسبند، نه به دستگاه.
پس با ورود به حساب، همه‌چیز روی هر دستگاهی برمی‌گردد.

- ورود به حساب: سندِ حساب خوانده می‌شود و جایگزین نسخه‌ی دستگاه می‌شود.
- اگر حساب هنوز کتابخانه‌ای نداشته باشد ولی دستگاه دارد، همان دستگاه بالا فرستاده می‌شود —
  کسی که قبل از ساختن حساب پلی‌لیست ساخته، چیزی از دست نمی‌دهد.
- هر تغییر، با کمی تأخیر (۰٫۸ ثانیه) روی حساب نوشته می‌شود.
- قاعده‌ی هم‌زمانی: **حساب برنده است.** سند جایگزین می‌شود، نه ادغام — پس پلی‌لیستی که روی یک
  دستگاه پاک شد، روی دستگاه بعدی هم پاک می‌ماند.

آنچه **همگام نمی‌شود** و عمداً می‌ماند: فایل‌های دانلودشده (بایت‌های صوتی در IndexedDB هر
دستگاه‌اند) و تنظیمات.

## بکاپ

```bash
bun run backup                              # می‌سازد
bun run restore .data/backups/muis-....json
```

بکاپ‌ها در `.data/backups/` می‌نشینند. بازگردانی، نسخه‌ی فعلی را کنار می‌گذارد و پس از آن باید
سرور را دوباره راه‌اندازی کنی.

## آرشیو متنی

```bash
bun run export
```

می‌نویسد در `data/muis-data.json` — یک فایل متنی که **در گیت می‌ماند**: نام کاربری‌ها، و هر
پلی‌لیست اشتراکی با فهرست کامل آهنگ‌هایش.

سه چیز عمداً در آن نیست، و هر سه اسرارند نه داده:

- **هش رمز و نمک** — هدف حدس آفلاین. تاریخچه‌ی گیت برای همیشه می‌ماند؛ حذف فایل بعداً آن‌ها را
  از کلون‌های قبلی پاک نمی‌کند.
- **کدهای بازیابی** — هر کد یعنی تعیین رمز جدید، بدون داشتن رمز قبلی.
- **نشست‌ها** — شناسه‌ی نشست مستقیماً توکن ورود است. از هش هم بدتر، چون هیچ کاری لازم ندارد.

پس این فایل **آرشیو است، نه راه بازگرداندن ورود**. حسابی که از روی این فایل ساخته شود رمزی
برای راستی‌آزمایی ندارد و کسی نمی‌تواند واردش شود. برای جابه‌جا کردن یک پایگاه‌داده‌ی سالم،
همان `bun run backup` است.

خروجی مرتب و بدون زمان است، پس هر بار که داده‌ای عوض نشده باشد فایل هم عوض نمی‌شود و
`git diff` فقط تغییرات واقعی را نشان می‌دهد.

## چه چیزی در گیت هست و چه چیزی نیست

**هست:** کل کد، `bun.lock`، اسکیمای D1 در `migrations/`، آرشیو `data/muis-data.json`، و همین
راهنما. از روی همین مخزن، هر پایگاه‌داده‌ای از نو ساخته می‌شود.

**نیست:** خودِ فایل `.data/muis.json`. داخلش هش رمزها، کدهای بازیابی و نشست‌هاست، و
commit کردنش یعنی دادن یک ورودی آفلاینِ رایگان برای حدس‌زدن رمزها به هرکس که مخزن را ببیند —
و تاریخچه‌ی گیت آن را پس نمی‌گیرد. به‌جایش از `bun run backup` استفاده کن و آن فایل را جایی
امن نگه دار.

## فرمان‌ها

| فرمان | چه می‌کند |
| --- | --- |
| `bun run dev` | سرور توسعه |

| `bun test src` | تست‌ها |

## استقرار

بیلد، خروجی ورکر Cloudflare می‌سازد:

```bash
bun run build
npx nitro deploy --prebuilt
```

پیش از این، `d1_databases` را در `wrangler.jsonc` پر کن. یک‌بار برای همیشه:

```bash
npx wrangler d1 create muis            # شناسه را می‌دهد
npx wrangler d1 execute muis --remote --file=migrations/0001_document.sql
```

شناسه را در `wrangler.jsonc` بگذار تا حساب‌ها روی سرور هم بمانند. اگر نام دیتابیس غیر از
`muis` است، همان را در `database_name` بنویس.
